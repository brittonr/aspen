# World Merge Root Absence Delta

## ADDED Requirements

### Requirement: Merge output kinds are explicit

r[molten.audit_f13.output_kind] Molten MUST distinguish absent roots, selected existing roots, and generated roots with a closed typed output contract that rejects contradictory fields.

#### Scenario: A merge selects an existing root

- GIVEN equal present source roots with matching admitted schema metadata
- WHEN merge planning runs
- THEN the output MUST identify the selected existing root without requesting generation.

#### Scenario: A merge generates an empty value

- GIVEN a supported semantic merge whose valid output is an empty value
- WHEN merge planning runs
- THEN the output MUST identify generated data explicitly and MUST NOT represent it as root absence.

#### Scenario: An output combines incompatible cases

- GIVEN a carrier that declares absence and also supplies generated bytes or a selected root
- WHEN output admission runs
- THEN it MUST reject the carrier before publication.

### Requirement: Publication preserves admitted root absence

r[molten.audit_f13.absence] Molten MUST omit an admitted absent root from the new root inventory without generating content, requiring a generated-output schema, or authorizing deletion of retained content.

#### Scenario: Both source roots are absent

- GIVEN a valid merge whose source roots are both absent and carry no schema metadata
- WHEN planning and publication run
- THEN the new inventory MUST preserve absence and the generated-root port MUST receive no call for that root kind.

#### Scenario: Absence includes compatible historical schema metadata

- GIVEN both source roots are absent and retain compatible schema metadata
- WHEN output publication runs
- THEN metadata alone MUST NOT cause an empty root to be generated.

#### Scenario: A root kind cannot be absent under its profile

- GIVEN a profile that requires a present root for a selected kind
- WHEN the merge proposes absence
- THEN planning MUST reject it before generated-root or commit publication.

### Requirement: Canonical output identity binds output kind

r[molten.audit_f13.compatibility] Molten MUST bind the output kind and its case-specific fields into canonical plan identity and reject legacy output carriers whose absence or generation meaning is ambiguous.

#### Scenario: Distinct empty and absent outputs have distinct identities

- GIVEN one generated empty root and one absent root under the same merge context
- WHEN their canonical output plans are identified
- THEN their identities MUST differ.

#### Scenario: An ambiguous legacy plan reaches publication

- GIVEN a legacy output with no selected root and no explicit generation or absence discriminator
- WHEN publication admission runs
- THEN it MUST reject the plan or require explicit re-planning without guessing its meaning.

### Requirement: Root absence has core and publication regression evidence

r[molten.audit_f13.validation] Molten MUST test absent, selected, generated-empty, malformed, unsupported, and legacy output cases through planning and publication with explicit effect observations.

#### Scenario: Complete supported merge publishes

- GIVEN a supported plan with absent and selected outputs plus any admitted generated outputs
- WHEN publication succeeds
- THEN it MUST publish the exact resulting inventory after every required generated root succeeds.

#### Scenario: A generated root fails publication

- GIVEN an admitted generated output whose persistence fails
- WHEN publication runs
- THEN Molten MUST NOT publish a successful merge commit, and existing heads MUST remain unchanged.
