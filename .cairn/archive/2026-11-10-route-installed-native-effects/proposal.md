# Proposal: Route explicitly admitted installed native effects

## Why

The public native host can execute real callbacks and durably retain approved effects, but an unrouted approved effect is not a collaboration commit or completed logical work. The current collaboration-scope consumer requires a concrete path from its installed native callback through an actual active Raft proposal and committed ScopeApplication transition to a real native completion callback. The parent explicitly authorized this separate prerequisite and its source registration on 2026-10-30. Source admission, callback success and queue acceptance cannot supply the missing effect authority or completion proof.

## What changes

- Add explicit, bounded, collaboration-only public runtime configuration binding the actual service, admitted manifest/port, group, active generation, policy, resource, installation and measured runtime artifact.
- Require independent current verifier-backed `install-effects` authority before effect-resource creation and exact `route-effect` authority before provider routing, in addition to the collaboration application's own fresh mutation authority.
- Retain the actual scope replica/application/router within the installed native host's serving-loop lifetime. Derive installation from the actual Running supervisor and admitted active group, never from a fixture or caller-ref claim.
- Compose existing Supervisor intent recording, effect routing and materialized completion delivery. Observe actual committed scope state before returning a commit completion; preserve approved effects instead of clearing them to imply success.
- Keep unconfigured effects and all post-effect uncertainty unresolved/fail-closed without automatic retries, implicit service activation, synthetic ports or manufactured receipts.
- Exercise the current collaboration consumer through a genuine materialized callback, real authority, real Raft application and actual completion callback.

## Non-goals

No generic plugin framework, source-trust-to-effect grant, queue-as-commit schema, model-only replacement, implicit group/service activation, production promotion, accelerator implementation or exactly-once external-effect claim. This source registration does not execute lifecycle gates, synchronize specifications, archive a change, commit or publish anything.

## Acceptance

An installed public native collaboration service must produce a genuine approved effect that enters its actual active bounded Raft runtime, changes committed scope state under fresh scope authority, and returns through its generation-fenced materialized native completion callback. Wrong/missing service, port, group, generation, policy, resource or current authority must not route. Uncommitted proposals, provider failures after possible effect and failed/unhandled completion callbacks must not mark logical work complete or authorize a retry. The actual runtime/router must remain owned by the node loop and process loss must retain the native/application uncertainty boundary. Recorded integrated execution remains a parent-owned acceptance prerequisite, not a consequence of source implementation.
