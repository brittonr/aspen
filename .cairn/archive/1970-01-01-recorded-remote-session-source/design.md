# Design: Capability-authenticated recorded session source

The receiver owns a Redb database opened through its node-state capability. One immediate-durability transaction serializes generation allocation and every committed operation. A session key binds both actual initialized node identities and topic. Each observation binds the previous observation hash, generation, sequence, operation, canonical payload and declared content refs. Histories are finite and overflow refuses before mutation. Generation never resets on close. The sender view borrows the live store and an exact generation; every build replays verified observations under a fresh read transaction and checks active generation, peers, topic, initialized identities and open state. No portable/imported snapshot constructor is exposed.

Generation counters are scoped to the logical `(sender node ID, receiver node ID, topic)` key. Bootstrap identity
replacement within that key requires a new generation. A receive observation additionally binds the exact canonical
input envelope ref; a local controller commit makes no received-envelope claim. This provenance field is not an
introduction or an authority grant, and it does not change the existing envelope wire shape.

The initial bounded profile permits 1,024 session keys, 4,096 observations per generation and 4 MiB per persisted session. A live generation reserves one observation and 1,024 bytes for its fixed close record, so capacity refusal cannot strand an otherwise valid generation. Closing and readmitting starts a fresh bounded history while retaining the monotonic generation and prior head binding.

An existing zero-length database, missing initialized session table, or Redb repair requirement refuses source opening instead of recreating generation one or silently rolling a close back. These failures preserve the recording artifact and require owner reconciliation with trustworthy committed-generation evidence; the profile offers no destructive reset or receipt-as-authority recovery fallback. This is an integrity refusal, not proof that a network peer retracted any reference.

Bootstrap is derived from both initialized node identities and the allocated session identity, never carried content/evidence/capability refs. The local controller's possession of both node-root capabilities admits the local recorded session only. Node identity parsing and successful output do not grant network authority.

Receiver mutation and observation commit are a single transaction. Replay runs the actual `RuntimeState` Assert/Retract/Send/Observe and actor-scope cleanup laws with fixed seed zero; there is no separate introduction ledger. The commit receipt binds its canonical observation and resulting runtime snapshot ref. A message cannot mutate the introduced set. Sender denial evidence uses a distinct versioned local build-denial record and names every unknown semantic reference; no envelope is published on refusal. Receiver admission denials return a canonical local outcome without committing runtime state, while database/commit errors remain errors rather than being rewritten as policy denial. The existing envelope wire representation remains unchanged.

Reopening the store preserves its last generation. A same-identity open generation must close before readmission; changed initialized identities require explicit readmission into a new generation. The new opening observation carries the prior committed generation head as provenance only, not as an introduced reference. A sender retains both source root capabilities and rereads their actual initialized identities; an old view refuses after close, readmission or identity replacement. Read-only runtime snapshots are outputs only and cannot construct views.

Semantic reference inventory: generic application payload content refs are extracted from values. `protocol-message-v1` contributes only `body-or-ref`: its protocol/schema identity and evidence metadata identify interpretation, not transferred object references. `job-worker-request-v1` contributes its job and execution-request workload operands; sync/admission receipts and authority/resource/peer-bootstrap/node-identity/evidence metadata remain independent gates, not introductions or payload capabilities. Declared envelope `content_refs` are checked separately. Carrying metadata can neither establish knowledge of a payload reference nor require treating protocol-schema hashes as capabilities. The introduction check never replaces delivery authority/resource admission.

The profile is local/recorded, not a claim of authenticated network observation. A future network profile requires a separately admitted transport or purpose-separated signatures plus currentness protocol. File root possession authenticates only this local recording boundary.
