# Design

The pure backend descriptor binds a SHA256 PCR selection, exact TPM2B_PUBLIC sealed-object bytes (including authPolicy and fixedTPM/fixedParent attributes), persistent handle, explicit provider identity and measured tool identity through canonical Preserves/BLAKE3. Only policy-only keyed-hash objects are eligible: userWithAuth is forbidden. The transport-only shell retains an executable and namespace workspace capability, clears environment, invokes the pinned unified tpm2 tool without a shell, bounds time and output, checks readpublic against the admitted object before unseal, and decodes exactly one MCKEY001 record from stdout into memory. Neither streams nor process errors are published. Typed policy/object/tool/timeout/unseal/record/handle outcomes never select another backend.

The existing production profile remains purpose-separated. Tpm2Sealed is eligible only for transport operations implemented here; signing remains capability-file. ManagedSecret eligibility is not loader evidence. A rotation request names its exact destination backend; its old opaque handle already binds the exact source. Existing same-backend requests remain unchanged; cross-backend admission is restricted to CapabilityFile/Tpm2Sealed, and completion checks the exact destination identity. Shell rotation completion compares the actually loaded next handle before producing existing transition evidence; activation/persistence remains the caller-owned fenced boundary.

A Nix rail uses the repository-pinned nixpkgs cohort, a private temporary swtpm state, a policy-only sealed record supplied on stdin, a persistent object, actual PCR extend, and the real Rust consumer. Every regular file in the consumer namespace is scanned for the record, seed and plaintext schema; the capability-file rotation namespace is separately scanned for the TPM record and seed while retaining its intentionally plaintext format. Emulator device-state authority is a sibling directory outside the consumer namespace, never a matching file excluded from its scan. Unencrypted software TPM state can serialize sensitive objects; no secret-free provider-state or physical-TPM storage claim is made. No seed or plaintext record is written by the sealed adapter or published as evidence. The rail cannot run against host hardware. Failure or unavailable tools is not passing evidence.
