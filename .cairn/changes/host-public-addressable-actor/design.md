# Design

The actor planner and `apply_request` remain the lifecycle owners; `Local` remains the actor state store. Native supervisors and their existing journals own actual callback execution. Coordination delivery owns claims and acknowledgements; the application effect owner must supply the durable semantic event/commit. Actor receipts must never turn a persisted lifecycle plan or successful callback into semantic completion.

A public semantic-outcome projection is independent of effect execution. It reports applied only for a durable, current actor delivery-completion receipt with successful terminal acknowledgement. It preserves duplicate replay separately and reports an uncertain commit/effect/status as unknown. Lifecycle progress remains progress even when a durable actor-state transition has occurred. Callers may retain and inspect canonical receipts; the projection grants no authority.

## Concrete owner composition

Aspen's existing assignment owner gains capability-rooted Redb persistence, current reads, and a same-transaction role-slot index keyed by extension/service/role (not node). Proposed initialization does not activate placement. Pure command validation precedes exact-state intent CAS, actual native lifecycle effects, and exact-intent commit. A pending intent blocks currentness without blind replay. Succession requires an exact Released predecessor and increasing epoch/token; this is node-local fencing, not cross-host exclusion.

An independently installed, always-running delivery extension owns the actual coordination-delivery `Local` mailbox. The actor native member may therefore drain while a new message is enqueued and claimed by its delivery owner. Delivery preview/admission binds exact request, persisted head, manifest/policy/time profile and native proof. Acknowledgement validates both distinct dispatchers; neither actor dormancy nor a fabricated `lifecycle_running` observation opens the mailbox.

The native actor drains rather than entering terminal shutdown. Sleep executes one exact checkpoint callback and then one drain callback through existing Host action intents. Rewake explicitly records runtime loss and executes Recover from the existing allowed phase with a fresh incarnation, unchanged generation and unchanged restart-attempt budget. Recover persists its closed-ingress incarnation fence before callback intent. An already Running StartRuntime observes the actual postcondition instead of issuing a second callback. Explicit actor StartSucceeded/RecoverySucceeded requests may bind that matching terminal Running postcondition, preserving exact key, placement, generation, checkpoint and pure planner checks.

The bounded counter guest is the actual measured native callback executable. Its admitted service identity is the canonical actor key; native instance identity remains unchanged. Canonical application state contains at most 128 logical requests and their original results. Checkpoint bytes equal current state; recovery validates exact checkpoint/state equality. Wrong-key, reused-ID-with-different-input, overflow and capacity cases reject rather than evicting dedup history. No guest filesystem, network, timer, entropy or provider-effect implementation is added.

Before terminal ingress the native owner publishes the original successful canonical callback receipt through its existing value/journal owner. Private NativeCommit proofs strictly decode/rehash those bytes and verify original ingress/callback/state-publication/receipt-publication history. The earliest exact record preserves the original event/commit identity across later work and process reopening; success is never reconstructed from a state reference alone. Public result observation requires native proof, actor completed-event metadata and the delivery owner's terminal row. Repeating a completed logical request reads that original result without another callback, acknowledgement or semantic commit.

Live fabric timers retain bounded actual TimerState and explicit logical-duration-to-clock-domain translation. Recovering claims reads the same mailbox, after exact authority admission. Idle sleep derives ready/in-flight counts and unresolved-native counts from current owners, not supplied zeroes. Quarantined dead letters are retained but not runnable sleep blockers. Runtime process, stream and session continuity remain unsupported survival claims.

## Credential transport and qualification

The public command retains one source-gated installed Owner. Interactive SIGN/READY transports only independently produced exact-operation credentials; Current remains the sole signature, policy, expiry, revocation, holder and replay authority. It prepares current load/status/effect/read/delivery requests immediately before their existing checks. READY is not admission. There is no host signing key, implicit trust, or simulated admission fallback.

Actual startup needs independently authenticated signed immutable candidate/source evidence and separately provisioned operator policy/keys. Implementation, authored fixtures and canonical identities are not executed cohort evidence. Positive/negative live qualification is retained only after the pinned commands actually run. The restored worktree resides on tmpfs; that location establishes no NVMe or machine-loss durability claim.
