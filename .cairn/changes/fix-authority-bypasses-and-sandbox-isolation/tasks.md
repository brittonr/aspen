Implementation notes:
- Task 1: `execution_request` admits against the unmodified template grant scoped only by the host-derived operation ref and the live instance generation (also passed as `active_generation`). The router admits the materialized output before recording; invalid output is recorded `Unknown` with no terminal ref; every post-delegate record failure returns `FabricPortError::uncertain`. Governing prose in `docs/native-system-extension-host.md` ("effect remains terminal when value admission fails") updated to match the delta requirement.
- Task 2: deviation from the task text, deliberately: `Engine::new_sandboxed()` was not used because, by source review of steel-core 0.8.2, it still registers the process/filesystem modules (nameable via `require-builtin`) plus I/O, time, and threads, and offers no metering. The executor uses `Engine::new_raw_no_kernel()` with only a metered primitive table, admits a closed definition language parsed with `Engine::emit_ast`, renames user identifiers into a private namespace, injects a fuel tick into every lambda body, charges primitive allocation (8 KiB per string, 64 KiB cumulative), admits hostcalls before dispatch, and calls the validated callable by name. `steel-core` features in `Cargo.toml` are unchanged (no `Cargo.lock` change): the raw engine registers none of the default-feature modules.
- Task 3: stdin bytes must hash to `stdin_ref`; the live adapter opens the executable once, requires a regular file, measures the handle's exact length, and spawns via `/proc/<pid>/fd/<n>`; `(operation_ref, generation)` recorded `Unknown`/`Terminal` returns `PortFailureKind::DuplicateOperation` (new variant) without spawning; definite pre-start failures stay retryable.

Tests added: `fabric_execution::tests::binding::{live_adapter_denies_stdin_bytes_that_do_not_hash_to_the_admitted_reference, live_adapter_measures_the_opened_executable_before_spawning, live_adapter_refuses_terminal_retries_but_retries_definite_prestart_failures}`, unknown-retry refusal in `tests::stdin::live_adapter_keeps_unconsumed_oversized_input_unknown_without_completion_claim`; `harness::steel` (`metal::tests`) `{legitimate_script_runs_with_real_metering_and_deterministic_receipt_inputs, ambient_filesystem_process_and_environment_access_is_unavailable, macros_mutation_and_non_definition_forms_are_rejected, shadowing_a_keyword_cannot_reach_the_compiler_namespace, anonymous_lambda_recursion_exhausts_real_fuel_deterministically, string_doubling_exhausts_the_memory_ceiling_before_fuel, hostcall_flood_is_refused_before_the_excess_call_dispatches, callable_injection_is_rejected_without_interpolation}`; `tests/nativesystemextension` `{native_execution_admission_denies_authority_that_differs_from_the_admitted_grant, native_execution_admission_denies_a_callback_generation_fenced_after_intent_commit, journal_failure_after_a_routed_effect_is_reported_uncertain}`; `materializing_native_host_rejects_missing_mismatched_and_oversized_effect_values_without_retry` now asserts `Unknown`, never `Terminal`.

Review fixes (FIX-FIRST round):
- Live adapter: per-adapter measurement cache keyed by executable identity plus the opened handle's `fstat` stamp (dev, ino, size, mtime, ctime); any change re-hashes, and a stamp that changes during hashing is refused. Executables open with `O_NONBLOCK` and non-regular files are refused (FIFO test). `operations` is keyed by `(operation_ref, generation)`. Hashing uses 1 MiB reads, and `[profile.dev.package.blake3] opt-level = 3` was added to `Cargo.toml` because unoptimized BLAKE3 needed tens of seconds for the 284 MB debug fixture (dev profile only; no `Cargo.lock` change). The authority test builds one cohort, starts an unmodified control, and clones it.
- Steel: primitives are registered only under private `molten-prim-*` names, so `(+ local k)` / `(- local k)` reach the metered, overflow-checked primitives. Each lambda evaluation is charged through a closure primitive (64 bytes plus 16 per in-scope or bound variable, plus fuel). Lambda and application arity are capped at 16. The VM runs on a dedicated 64 MiB-stack thread.
- New tests: `binding::{live_adapter_rejects_a_fifo_executable_without_blocking, live_adapter_remeasures_an_executable_changed_after_a_cached_measurement}`; `metal::tests::{closure_chain_is_bounded_and_dropped_off_the_callers_stack (runs from a 2 MiB thread), closure_creation_counts_against_the_memory_ceiling, arithmetic_on_locals_reaches_the_metered_checked_primitives}`.
