## Notes (tasks 4–6)

- Job DAG admission (`src/job/parts/dag/p011/body.rs`) has no independent principal or key source. It now calls the separately named `authority::admit_capability_scope` (capability, scope, attenuation, validity, revocation only), whose receipts always carry `principal-and-key-currentness-not-claimed`. Binding job admission to an independent principal/key source is an explicit non-claim, documented in `docs/technical/capabilities/revocation-and-stale-authority.md`.
- File-adapter revocation markers are now a canonical revocation set (`fabric-crypto-key-revocations-v1`; the earlier single-record marker still parses). A record denies its exact handle at its generation and any handle exposing the same public key; malformed markers fail closed; a missing key leaf with any revocation never mints a first-boot replacement. `revoke` reads, extends and publishes the set under one per-leaf update lock (`Scope::lock_update`), and a revocation that would add a 65th record is denied before publication.
- `verify` gates cryptographic success on the verifying key being the domain's declared signer; the existing wrong-key assertion now expects `CryptographicVerificationFailed` instead of the formerly overwritten `SignerPublicRefMismatch`.
- SpaceWasm binds the credential policy by recomputing the existing `spacewasm-isolated-fixture-authority-v1` identity (issuer, holder, exact `policy_json`, resource) and comparing it with `current.authority_ref`; the fixture uses the same function, so its authority ref is unchanged.
- `DagResourcePort` gains a required `confirm` method (re-observe an existing reservation without reserving again); the federation live port confirms against its persisted reservation leaf.
- Publication artifacts are named `.stage.{leaf length}.{leaf}.{kind}` (length-delimited, so no leaf's cleanup matches another leaf's stage or lock). The `.stage.` prefix is reserved in both `RelativePath::parse` and the local-store `Locator::parse`, so every node-state and local-store write, publish, create, rename and remove refuses such a name before any filesystem effect (compatibility note in `docs/node-state-filesystem-authority.md`: stored names in this namespace are rejected, not migrated); node-state listings skip publication artifacts. Every publication holds the leaf's `lock` while it settles, and read-modify-write updaters hold a separate `update-lock`; a holder unlinks a lock file only if it created it. Before blocking on a pre-existing lock file, the opened handle must have mode 0600 or stricter and be owned by the node-state directory's owner or the process's effective owner, else publication fails with `FailureClass::CapabilityUnavailable`. Cleanup removes only exact `…stage-{process}-{sequence}` names with decimal parts; earlier-format `.{leaf}.stage-…` stages stay hidden and untouched. `SourceError` gains `UnsafeMember` (non-regular or world-writable bundle member).
- Membership receipts are now `raft-membership-receipt-v2` with `.v2` schemas and carry `request-ref`, a canonical digest of every request field including all ten evidence categories; `commit` compares it with a fresh preflight of the request and denies any v1 preflight ("v1 lacks a request digest").
- Concurrency regressions use test-only seams at the vulnerable boundaries: root `open_existing` immediately before the open, `protected()` mode check→read, `sign` observe→sign, `revoke` after the update lock and before the read, `revoke` read→publish, and node-host's leaf-lock acquisition (immediately before `flock`). The node-host lock seam is compiled for its own tests and for the dev-only `test-seams` feature, which the root crate enables only through `[dev-dependencies]` (no new crate, no `Cargo.lock` change). In the revocation regression A pauses between its read and publication and waits for B's first boundary event: with the update lock it is B's lock acquisition; without it, it is B's read, whose hook observes the pre-A set and fails, so the lost-update code fails deterministically.
- Pre-existing lock files are reusable when owner-only and owned by either the node-state directory's owner or the process's effective owner. `rustix::process::geteuid` was tried (rustix 1.1.4 is already in `Cargo.lock`; the only lock diff was one dependency-edge line), but `nodehostboundary::production_and_positive_manifests_admit_only_node_host_dependencies` enforces `r[molten.node_host.crate_boundary]` (only cap-fs-ext, cap-std and molten-core), so it was reverted and `Cargo.lock` is unchanged. The effective owner is instead read from a collision-safe owner-only probe under the reserved prefix: an existing probe name (crash-left or concurrent) is reclaimed and the next sequence tried, and unlink errors other than not-found are reported. Tests: `the_owner_probe_reclaims_crash_left_probes_and_leaves_nothing_behind`, and `a_crash_left_lock_of_a_writer_that_does_not_own_the_directory_is_reusable`, which asserts the directory owner differs from the writer's uid before exercising reuse (as root: a temp dir chowned to 65534; otherwise the root-owned `/tmp`).
- `workload::tests::hegel_blob_ref_submission_rejects_inline_tokens_and_records_pin_lifecycle` failed once in a broad parallel run with Hegel's wall-clock `FailedHealthCheck: TooSlow`. It passes in isolation (78 s on this worktree) and the unmodified main checkout takes 143 s for the same test in isolation, so this is a pre-existing slow-test flake under contention, not caused by these changes; the test touches no `.stage.` names.
- The TPM2 unseal path uses the same handle-scoped revocation check; the swtpm-backed `load_pcr_denial_secrecy_and_rotation` test remains `#[ignore]` and was not run.
