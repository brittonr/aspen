## Verification (2026-11-26, tasks 1–4: fabric_time + fabric_membership)

Audit claims 1–4 were confirmed against the code before changing it. Implementation notes:

- `expire_reservation` accepts `Committed` or `Stale`; a `Released` record fails closed with `ExpiryIssue::AlreadyReleased` (replacing `NotStale`). Release restores pool and the assigned worker with checked arithmetic; `capacity_invariant_holds` now also requires pool reserved/allocated to equal the sum of held (`Committed`/`Stale`) reservations.
- `Owner::reserve_batch` (and `reserve`) commit each item to `self.state` right after its allocation succeeds; the first allocation failure stops the batch and returns `Failure::Classified` with the port class. An `UncertainExternalOutcome` keeps the item's reservation committed (capacity held until an enforcement fact).
- `LeaseAction::Renew`: `FencedExclusive` requires `fencing_token` and `previous_fencing_token` (`DeniedWithoutFencing` otherwise) and denies `token < previous` as `DeniedStaleFencingToken`; `LocalObservationOnly` renewals carrying fencing tokens are denied without fencing.
- `AssignmentPersistence` gains `inspect_pending`, `abort_pre_effect_intent`, `reconcile_pending_intent`, `quarantine_reconciliation`, `reconcile_legacy_quarantine` and `initialize_quarantine_successor`. Recovery never trusts caller-built evidence: abort and `ConfirmObservedEffect` ask the role lifecycle port (`ExtensionRoleLifecyclePort::observe_intent`, default `Unknown`) and require `NotExecuted`/`Executed` evidence bound to the exact assignment, command transition ref, kind and intent ref; effectless transitions abort from the persisted kind. `QuarantineUncertain` quarantines (with `uncertain_old_owner` set and an intent-derived transition ref) only after a new `QuarantineAuthorityPort` returns an authorization echoing the exact request; no caller evidence ref exists. Entering `Quarantined` persists an owner-computed reconciliation record with an explicit basis (committed effect, reconciled intent, legacy record) in Redb table `fabric-assignment-quarantine-reconciliations-v1`; stores written before that table open unchanged, and `reconcile_legacy_quarantine` migrates their quarantined records under authorization bound to the record's quarantine transition. Succession (`validate_quarantined_successor`) checks the persisted record and a fence observed through `FencingAuthorityPort` at the strength `minimum_quarantine_succession_enforcement` derives from node identities (same node: node-local durable; cross-node: quorum-ordered or stronger); callers no longer choose it.
- `src/addressable_actor/command/placement.rs` (outside the original task file list, required by review): the placement `Lifecycle` records activations refused before any native effect (`actor_preview` / `signing.prepare` failures, via a `NativeActivation` seam) and reports exactly those as `NotExecuted`; `placement step` aborts such an intent through `abort_pre_effect_intent`, so the next step reads `current()`. A lost `actor_rewake` outcome stays pending and uncertain.
- Placement candidates sort healthy-first; degraded replicas are admitted by increasing budget (0..=replicas), so plans use the fewest degraded nodes. Each pass is skipped without search when healthy plus at most `budget` degraded-only anti-affinity values cannot cover the replicas, and a non-final pass that hits the step bound falls through with residual capacity restored, so the degraded fallback is always reachable. Failure reduction is keyed per `(subject, time_basis_ref)` with a total order, then folds across bases by severity without comparing ticks.
