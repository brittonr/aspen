## Verification (2026-11-26, coordination task 5)

Audit claims confirmed against the code before changing it: committed `LockState`/`ElectionState` kept `pending_token(...)`'s `token_ref` (bound to `fixture_ref("pending-coordination-commit")`), the receipt's `dataspace` refs named an assertion bound to `fixture_ref("coordination-mutation-placeholder")` (reads: `coordination-read-placeholder`) that was then discarded, no lease expiry or resignation existed, and `new_coordination_runtime` always used `control_registry_fixture_manifest_value()`.

Implementation: the control registry now commits a token-free `coordination-commit-intent-v1` (request, before state, after state without claimed entries, token claims, clock sample); the commit shell issues each `FencingToken` bound to the resulting commit receipt and inserts the lock/election entry with exactly that `token_ref`. `coordination-status-assertion-v3` binds the control-plane receipt (commit or registry read receipt), so the coordination receipt lists the emitted assertion's ref. Lease time comes only from a shell-owned `CoordinationClock` port (a `fabric_time` `TimerClockAdapter` bound to a time basis) injected into the runtime: `CoordinationClock::live()` is the node monotonic clock under an admitted live time profile (nanosecond ticks; basis ref binds the profile and its anchoring wall instant), and `CoordinationClock::fixture(ticks)` is the deterministic clock for `run-fixture`, simulations and tests. The runtime samples it once per admitted mutation; a sample from another basis or below the committed time is denied, and each committed mutation records `(time_basis_ref, ticks)` in the state (`coordination-state-snapshot-v2` `time` record, alongside each lock/leader `lease_expires_at`), in its commit intent, and in `CoordinationApplyResult::time_sample`. Mutation-count time was removed. No committed sample may pass `MAX_COORDINATION_TIME_TICKS = u64::MAX - MAX_COORDINATION_LEASE_TICKS`, so every lease expiry is representable; tick/expiry arithmetic is checked. Acquire/elect take an optional `<lease ttl>` (1..=`MAX_COORDINATION_LEASE_TICKS`, default `DEFAULT_COORDINATION_LEASE_TICKS`, 30 s / 1 h on the live basis); `expire` (lock, election) takes no payload and succeeds only once the clock sample reaches the expiry; `resign` (election) takes `<token n>` from the leader only. `new_coordination_runtime(manifest, clock)` fails closed on a foreign `control_group_ref`; `new_coordination_runtime_with_control_group(manifest, group, clock)` binds an explicit group manifest. CLI callers (`coordination apply`, job worker schedule) pass `CoordinationClock::live()`. Ledger artifact kinds and `preserves_rail` schema constants were bumped accordingly.

Review fixes (FIX-FIRST, three rounds): the first revision accepted caller-presented `<now ticks>`, so any authorized caller could expire a live lease or commit `now = u64::MAX` and wedge later grants on overflow. The second counted committed mutations as time, so a non-holder could age a live lease by committing unrelated mutations while an idle crashed holder never expired. Time now comes only from the shell-owned clock port described above. The third round fixed two remaining gaps:

- **Clock failure:** a clock-read failure was recorded as a denial under the operation id, so retries replayed it. `apply_coordination_request` now returns the port's classified `Failure` before it records anything.
- **Clock basis change:** a recreated live clock (new basis, restarted ticks) denied every mutation. The runtime clock is now private, and a new basis is installed only through `transition_coordination_clock(runtime, clock, authority_refs)`. That commits a `coordination-clock-transition-v1` record (from/to samples, before/after state refs) through the control registry at `coordination:clock`/`time-basis`. It re-anchors each lease that was live at the last committed sample to expire its full granted TTL (now recorded as `lease_ttl` in lock/election state and token claims) after the new basis start; leases already expired at a committed sample stay expirable. Holders, tokens, token refs and `next_fencing_token` are preserved.
- **Clock provenance (fourth round):** transition authority refs were only shape-checked, so code holding a fabricated ref could install a frozen clock and stop leases from expiring. Now:
  - **Fixture clocks gated:** `CoordinationClock::fixture`/`fixture_on_basis`/`new` exist only under `cfg(any(test, feature = "test-fixtures"))`, the existing dev-only feature.
  - **Live-only transitions:** `transition_coordination_clock` accepts only a sealed live clock (a private `LiveClock` variant that only `CoordinationClock::live()` builds). Its basis ref must match its provenance: the admitted lease-clock profile, the wall anchor of its monotonic origin, and a process-local open sequence. The runtime's current clock must also be live.
  - **Simulation path:** `run-fixture` and simulations use `new_coordination_simulation_runtime`, whose deterministic clock is frozen at zero and never transitions.
  - **Reachability:** a grep shows no caller outside the coordination module and no request operation or CLI command reaching the transition. It is documented as a node-local shell operation, and it is still recorded as a committed `coordination-clock-transition-v1`. Deterministic re-anchoring and replay tests drive the private commit core with fixture clocks.
- **Lease extension and feature gating (fifth round):**
  - **Remaining-TTL re-anchoring:** repeated genuine live transitions each re-anchored a lease to its full TTL, postponing expiry forever. Re-anchoring now uses the remaining TTL: the old expiry minus the latest observation of the retiring basis, saturating at zero. The observation is a fresh sample of the retiring clock when it still reads, otherwise the last committed sample. It is recorded as the transition's `from` sample, so replay passes it back. `lease_ttl` was removed as no longer needed.
  - **Node capability:** the transition is now a private fn. The only public entry is the node capability `recreate_coordination_live_clock(runtime, authority_refs)`, which opens its own sealed live clock, so a caller cannot pass in any clock.
  - **Live-only production constructors:** since `test-fixtures` can be enabled downstream, `new_coordination_runtime` and `new_coordination_runtime_with_control_group` now reject any clock that is not a sealed live clock with matching provenance, whatever features are enabled. Deterministic clocks are accepted only by `new_coordination_simulation_runtime(manifest, clock)`, which in turn refuses live clocks.
- **Shared-instant translation (sixth round):** `from` was sampled before validation and `to` after it, so time spent between the two samples was lost and an expired lease could stay live. Now:
  - **Validation first:** the commit core runs every check before reading time.
  - **Single reading:** live clocks count nanoseconds from an origin `Instant` on the node monotonic source (one `read_node_monotonic_instant`, allowed under `tigerstyle::ambient_clock` like the fabric_time live adapter). One reading is converted into both bases, and `new_expiry = new_now + (old_expiry - old_now)`, saturating at zero.
  - **Restart gap:** a retiring clock that no longer reads on the committed basis is credited only up to the last committed sample; this conservative gap is documented.
  - **Injectable source:** the commit core takes the shared-reading source as an injectable closure. The live path uses `live_shared_reading`; tests inject a modelled instant source.
