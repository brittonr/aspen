## Why

Direct audit of Aspen's replicated Raft engine (`src/fabric_consistency/raft/`), live Iroh transport (`src/fabric_transport/cross_process/iroh/`), and live reliability host (`src/reliability/service/`) uncovered multiple critical liveness, safety, and security flaws that cause a live 3-node cluster to self-destruct, wedge permanently, or accept spoofed/replayed messages:

1. **Timer self-destruct on election win, step-down, and normal timer races:** `TokioReplicaPort::arm_heartbeat_timer` (`src/fabric_consistency/raft/time/mod.rs:205-215`) never aborts `election_handle`, and `arm_election_timer` (`L179-L203`) never aborts `heartbeat_handle`. When the stale timer fires, `election.rs:21-75` returns `Err` → `ReplicaExecutionOutcome::Denied`, and `Host::serve_bound` (`src/reliability/service/host/runtime.rs:125-128, 239-248`) propagates `?`, killing the leader or follower. Even with handle cancellation, any already-queued stale `ElectionTimeout` in the `mpsc` channel after an `AppendEntries` timer reset produces the same fatal crash.
2. **Linearizable `ReadProbe` crashes lagging followers:** `read.rs:25-27` returns `Err` when `input.required_index > last_log_index`. Because `begin_linearizable_read` broadcasts `ReadProbe` to all peers, any follower even one entry behind `commit_index` discards higher-term updates and dies in `Host::serve_bound`.
3. **Log reconciliation deadlock on retried `request_ref`:** `replication.rs:53-55` calls `validate_incoming_entries` (`validation/p000/body.rs:215-223`) *before* `merge_entries` truncates conflicting uncommitted entries, scanning the entire log including uncommitted entries scheduled for truncation. A healed old leader holding uncommitted `(index 2, term 1, R1)` permanently rejects the new leader's committed `(index 1, term 2, R1)` and crash-loops on restart.
4. **Leader commit permanently wedges at `>= 125` entries:** `advance_leader_commit` (`replication.rs:190-200`) jumps directly to `highest_quorum_index` without chunking, emitting `N + 4` effects (including durable fences in `executor/batch.rs:18-24`) against `max_effects_per_step = 128` (`recipe/node.rs:93-97`). Similarly, a follower holding `max_log_entries` (4096) entries rejects `AppendEntries` before `snapshot_if_due()` can run.
5. **Recovery snapshot violates log-term monotonicity:** `rejoin::repair::install_snapshot` (`rejoin/repair.rs:187-196`) unconditionally retains local suffix entries after `last_included_index` (`is_suffix_retained: true`) without checking boundary term equality, causing `validate_log` to reject recovery when uncommitted entries have `term < last_included_term`.
6. **Unauthenticated Raft Iroh transport and remote DoS kill:** `Listener::poll_one_derived_frame` (`iroh/parts/shell/p001/body.rs:172-176`) accepts any remote `EndpointId` and self-echoes `expected_peer_context_ref`; `received_event` (`raft/iroh/mod.rs:177-191`) never binds transport identity to `envelope.from`; and any single stalled peer handshake returns an `Err` that kills `ReplicaIngressPump` (`pump.rs:33`) and the host.
7. **Cross-node replay of signed `Teardown` / post-failover `Write`, plus swallowed quarantine:** `Host::admit` (`runtime.rs:145-189`) accepts `request.endpoint` matching any cluster peer while replay nonces (`operator/access.rs:50-57`) are node-local files—allowing one signed `Teardown` from Node A to be replayed to B and C to shut down the entire cluster, and compacted writes to be replayed after failover. Meanwhile `Host::perform`/`wait` (`operation.rs:40-81`) swallows `ReplicaExecutionOutcome::Failed` quarantine instead of stopping the host.
8. **Fast-path ledger bugs (`src/fabric_consistency/fastpath/stable.rs:81-156`):** `ApplicationLedger::converge` deduplicates globally on `command_ref` across distinct sessions while allowing conflicting `(session_ref, session_sequence)` retries, and `evaluate_stable_view` counts acknowledgements without checking replica membership.

## What Changes

- Cancel opposing timers on role change in `TokioReplicaPort`, and treat stale or role-mismatched timer events as benign ignored no-ops in Raft transitions / `Host::serve_bound` rather than fatal `Denied` exits.
- Fix `ReadProbe` handling so lagging followers confirm current-term leadership without requiring `last_log_index >= required_index` and preserve higher-term updates.
- Run duplicate `request_ref` validation only against retained prefix entries (`index <= prev_log_index`) and committed/non-truncated log entries, after resolving conflicting suffix truncation.
- Chunk leader commit advancement within `max_effects_per_step` and permit bounded snapshot compaction before rejecting `AppendEntries` at `max_log_entries`.
- Fix `rejoin::repair::install_snapshot` to check boundary term equality before retaining suffix entries (matching normal `InstallSnapshot`).
- Authenticate live Raft Iroh connections against the actual remote `EndpointId` and bind `remote_transport_identity_ref` to `envelope.from`; isolate per-connection handshake/timeout errors inside `ReplicaIngressPump`.
- Scope local `Teardown` requests strictly to `self.admission.endpoint`, harden write replay deduplication across failover/compaction, enforce fail-stop exit on `ReplicaExecutionOutcome::Failed` in `Host::perform`/`wait`, and fix `fastpath/stable.rs` session deduplication and voter membership checks.

## Impact

- **Files**: `src/fabric_consistency/raft/time/mod.rs`, `src/fabric_consistency/raft/transition/{election.rs,message/read.rs,message/replication.rs,parts/validation/p000/body.rs,rejoin/repair.rs}`, `src/fabric_consistency/raft/iroh/{mod.rs,pump.rs}`, `src/fabric_transport/cross_process/iroh/parts/shell/{p001,p002}/body.rs`, `src/reliability/service/host/{runtime.rs,runtime/operation.rs}`, `src/reliability/service/operator/access.rs`, and `src/fabric_consistency/fastpath/stable.rs`.
- **Verification**: Deterministic simulation, unit, and multi-process loopback regression tests reproducing every one of the 8 failures above (election win past election timeout, step-down past heartbeat tick, `ReadProbe` against lagging follower, partition heal with retried `request_ref`, 128-entry batch commit, conflicting-term recovery snapshot, spoofed `envelope.from` / stalled handshake, cross-node `Teardown` replay, and fail-stop quarantine).
- **Non-claims**: Repairing these protocol and host defects restores basic live Raft liveness and peer authentication on loopback/local clusters; it does not establish cross-host WAN qualification or production release readiness.

## Out of Scope

- Fixing `raft::membership::commit()` or single-process `coordination` state wedges (tracked in `fix-authority-bypasses-and-sandbox-isolation` and `eliminate-time-membership-and-coordination-state-wedges`).
