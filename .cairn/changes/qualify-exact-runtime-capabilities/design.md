## Design

The shell reads explicit matrix, mapping, subject and artifact inputs. The deterministic core joins existing matrix definitions to the reviewed requirement/owner/profile/family mapping. Each applicable requirement/family needs positive and negative native observations or the existing reviewed exemption. Canonical failure wins over pass; malformed, partial, unbound or mismatched supplied evidence prevents bounded-observed. Matrix commands/caveats/exemptions remain distinct from execution artifacts.

The native producer calls existing current-process signed-source admission before executing the existing fixed harness scenarios. Actual native reports/failures, fixed suite, canonical source validation and observed exact subject are embedded in a canonical execution receipt. No caller can choose its requirement/family/coverage decision. The positive scenario reuses examples/two-actor.preserves; the negative fixture exercises missing-grant denial through the same runtime and validators. Native validation and replay reuse existing receipt semantics rather than a second test/runtime core.

For readback, the existing selected-output validator authenticates/rechecks the full immutable signed output and measured closure. Bounded Exec invokes that selected bin/molten in read-only readback mode; that process authenticates/re-measures itself, reports its actual compiled features/platform and fixed simulation profile/adapter, then executes/replays both fixed pure simulation scenarios without files or live ports. Successful supplied receipts must match those actually observed canonical runtime execution identities, not merely metadata from a caller-authored carrier. Receipt subject and input must match the independently observed facts even if edited together. Source identity is the exact admitted NAR ref, not an unattested Git label. The report tool's own build features or replay do not substitute for actual execution of the selected product. Metadata-only describe remains separate for input construction.

The six product views retain unsupported/not-recorded scopes and their required families. The additional harness-runtime-capability-binding row can qualify only the exact finite simulation. A native process hosting a simulation does not become distinct-process distributed evidence. Missing product-family producers or unavailable external checker cohorts are not synthesized, substituted or marked complete.

Output is canonical packed Preserves over the existing canonical JSON projection, with stable JSON/Markdown review views. The report is read-only: source readback and deterministic native validation/replay perform no product mutation, signing, deployment or release changes. Actual scenario execution is a separate explicit CLI action. No paths, process ids or clocks become report subject identities.

Trust assumptions are the independently authorized source signer, approved verifier/store/kernel and reviewed native producer. Source signatures do not sign run results or supply remote attestation. Explicit cfg(test) source tokens test pure validator laws only; production tokens come only from existing source admission.
