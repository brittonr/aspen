# Admitted direct-LAN streaming

Aspen exposes the explicit `molten-iroh-direct-lan-stream-v1` implementation profile through its existing cross-process Iroh transport. `molten` remains the internal crate/CLI/schema name. This document describes the consumer contract, not a claim that a two-host or VM migration run has passed.

## Selection and compatibility

The selected dependency cohort is registry **Iroh 1.0.0**, backed by **NOQ 1.0.0** in this repository's lockfile. The existing explicit-loopback `Listener`/`exchange_frame` conformance API and its canonical artifacts are unchanged. Direct streaming is a separately selected profile: it does not widen the loopback profile's bind policy or turn its receipts into cross-host evidence.

At Kiln revision [`90acb852940fa97aa55b4cc1559db835d1dacc12`](https://github.com/OnixResearch/kiln/tree/90acb852940fa97aa55b4cc1559db835d1dacc12), the workflow adapter selects Iroh **0.95.1**, while `runtime/kiln-aspen-host` selects an older Aspen/Molten revision. Those are not the selected stream cohort. No external repository, dependency pin or lockfile is changed here, and 0.95.1/1.0.0 wire compatibility is **not** asserted.

The explicit compatible composition to evaluate is a Kiln migration-side host bridge built against this Aspen revision and its Iroh 1.0.0 closure. It uses this public protected-socket API, rather than passing Iroh 0.95.1 connection types across the boundary. Kiln's existing 0.95.1 workflow control adapter remains separate and unchanged. Kiln must select and retain its exact host-runtime revision, complete dependency closure, migration adapter and Cloud Hypervisor version before that composition can be qualified. A source-level handoff is not execution evidence or permission to repin Kiln silently.

## Consumer API and authority order

The public Rust facade is `molten::fabric_transport`:

1. Supply the canonical `Profile` and `ProtocolDescriptor`, exact active generation, endpoint capability, explicit numeric unicast bind and direct IP handoff. `validate_direct_stream_bounds` requires the direct profile id, one admitted connection and one bidirectional stream. Do not use wildcard binds, relay/custom locators, ambient discovery or endpoint fallback.
2. The server calls `direct::Acceptor::bind(direct::Config)`; its configured peer context must equal `listener.expected_peer_context_ref` before binding or publishing a handoff. The client supplies `direct::Outbound { input, peer, bounds, request, clock }` and calls `direct::proxy`. `input` retains the normal exact endpoint-import expectations. Both configuration inputs and `RegisteredStreamRequest` receive an explicit monotonic `clock: fn() -> std::time::Instant` from the imperative consumer, normally `std::time::Instant::now`. These compose existing endpoint, listener and session owners; there is no new transport, scheduler or membership protocol.
3. A complete Iroh handshake supplies the actual `Connection::remote_id()` and negotiated ALPN. The binding must match the configured EndpointId, peer context, service, ALPN, remote client/listener role and active generation. Expected peer context is applied only in conjunction with an exact authenticated key match; it is not accepted merely because it was copied from a handoff.
4. The listener derives the rate source from `Incoming::remote_addr()` (IPv4 address or IPv6 /64, not a cheap-to-mint endpoint identity). `ReceiveGate` consumes an injected-time budget before the costly service handler. Only this gate constructs non-Clone `GatedInbound`; both private construction and the actual protected-service handler boundary have compile-fail coverage. The limiter covers service admission, **not** all QUIC/TLS handshake CPU.
5. The peers exchange a fixed 32-byte canonical operation-binding digest before payload. It binds request, operation, protected resource, generation and the complete stream contract. A mismatch denies before opening a local socket. Full-handshake-only APIs and an explicit `RecvStream::is_0rtt()` check refuse replayable early stream operations.
6. Implement `ProtectedSocketService::authorize(GatedInbound, &DirectStreamRequest)`. This trusted consumer port resolves current membership, application principal, trust, capability, expiry and revocation for the exact operation. It returns a canonical evidence ref, not an authority grant inferred from connectivity. No default production authority or fixture fallback is supplied.
7. `check_current(&direct::AdmittedOperation)` runs before local opening and each frame. `open` receives a privately constructed admitted operation and returns a protected `tokio::net::UnixStream`. The consumer must resolve it through its existing protected root and recheck currentness at the protected effect; the transport accepts no ambient socket path.

For registered extension effects, retain the existing `Registered` port and register a payload-free bidirectional `TransportCommand::OpenStream`. Call `Registered::proxy_stream` with `RegisteredStreamRequest`, the exact canonical binding and typed effect. The ordinary `FabricEffectPort::route` rejects `OpenStream` for the direct-stream profile; other profiles retain control-only setup for their bounded-frame path. Both the registered request reference and `OpenStream.operation_id` must match the protected request before applying a transition. Existing extension/service/generation/profile/target admission still precedes the transition, and the request is consumed before network effects. The protected stream never enters `Registered`'s `Vec<u8>` frame queue. Its terminal evidence, not closure of the control handle, owns delivery and uncertainty.

Neither endpoint possession, successful source admission, authenticated peer identity, a historical receipt nor transport ACK grants VM/storage authority. Kiln retains workflow attempt, placement, destination resume, migration cutover and result authority.

## Bounds and lifecycle

`DirectStreamBounds` is explicit and included in a canonical stream-contract ref exchanged by both peers:

- One admitted operation/connection and one bidirectional stream; the mutable listener serializes callers. Extra incoming attempts are refused while the selected operation runs. There is no spawned transfer worker or hidden transfer queue.
- A maximum payload frame size (at most 1 MiB), total payload bytes **per direction**, frame count **per direction**, idle timeout, total operation deadline and separate `cleanup_timeout_ms` (each total/cleanup deadline at most 300,000 ms). Operation execution and its cleanup have separate finite budgets; the timeout does not silently abandon cleanup or claim it succeeded.
- Two fixed application frame buffers. QUIC receive and send windows are each `2 * max_frame_bytes + 512`. The admitted queued/in-flight payload/control budget must therefore be at least `6 * max_frame_bytes + 1024`, and at most 64 MiB. No VM RAM image is collected in memory.
- Pending unauthenticated handshakes are a separate selected-runtime bound: NOQ 1.0.0 defaults to 65,536 pending attempts, 10 MiB buffered per attempt and 100 MiB aggregate incoming buffered data. Iroh 1.0.0 does not expose a builder setter for these endpoint-wide defaults. These bounds are **not** included in `max_buffered_bytes`, and this source gate does not claim pre-TLS DoS protection. An operator needing smaller endpoint-wide unauthenticated bounds needs an admitted upstream/configuration change; do not report the application payload limit as a total endpoint/RSS bound.
- One unacknowledged outbound frame, no application frame backlog, QUIC backpressure and no consumption of another local frame until its acknowledgement. After an exact byte/frame bound, a one-byte overflow/EOF probe is the maximum extra local consumption; a consumed overflow is reported and never replayed.
- Partially read headers remain in the driver across readiness changes. Cancellation-safe `read` is selected against local readiness; dropping a partial `read_exact` is not used to restart a header.

The framed stream has a nine-byte kind/unsigned-64-bit prefix. DATA carries a 32-byte BLAKE3 digest followed by the bounded payload. ACK carries the corresponding sequence and digest and is emitted only after a matching bounded protected-socket write. FIN carries zero length, half-closes the protected local writer, and receives an empty-payload digest ACK. Either direction can continue sending after the other half-closes. Both FINs and definitive ACKs precede stream finish, a fixed one-byte trailing-EOF probe, and bounded observation that the peer received all final stream bytes. The listener owns clean connection closure while the client keeps its endpoint alive to acknowledge the listener's final bytes; failure still resets either side immediately. The wire framing is internal to this selected profile, not an interoperability assertion for other Iroh/application versions.

A watch cancellation signal or loss of its sender terminates the operation **while the API future continues to be polled**; idle/total timeouts, revocation, malformed framing, over-bound input and disconnect also terminate it. Local connection close with a nonzero code resets the failed operation. Local connection/endpoint closure is awaited within `cleanup_timeout_ms`; a timed-out cleanup remains `cleanup_observed=false`, even if the earlier byte acknowledgement was definitive. Consumers must check cleanup separately from delivery/stream terminal class. A cancelled handshake without an authenticated connection handle closes and drains its owning endpoint rather than fabricating cleanup from dropping the handshake or silently rebinding. Unobserved listener cleanup stops further admission and retains its active reservation for reconciliation. Dropping the API future itself bypasses its asynchronous cleanup and produces no terminal evidence; it is not the supported cancellation handshake described here. `reset_observed` records local reset initiation, not a remote application acknowledgement or proof of cleanup.

`begin_drain` or `begin_drain_with_reason` stops new protocol admission; registration, capability and profile revocation use the existing drain-reason enum. An active operation is bounded by its deadline and can be stopped through its cancellation owner/current-authority port. After its terminal observation, `drain_and_close` awaits endpoint cleanup. An already-draining listener is completed without applying a second BeginDrain transition. A pending/new generation cannot inherit an old consumed operation.

## Delivery evidence

Every completed API invocation returns canonical `direct::Evidence.value` and its BLAKE3 `evidence_ref`. It binds exact descriptor, operation, contract, actual authenticated peer (when available), configured peer context/service/ALPN/role/generation, observed direct path class, bytes/frames, local consumption, acknowledgement count, duration, receive denial code, operation-authority evidence and local cleanup. Raw payloads, keys, locators and local socket paths are excluded.

`Delivered` means the selected transport/socket-write acknowledgement boundary completed. A failed operation is `NotDelivered` only if protected-service opening has not started and there was no local consumption, submission or protected write. Starting `ProtectedSocketService::open` is already possibly effectful: it can connect or write before returning a socket. The private progress marker is therefore set **before** awaiting `open`; cancellation, timeout or an error after that point is `Uncertain` even with zero transport/local-consumption byte counters and no returned socket. Consumption, submission or a possibly partial protected write without full completion is also `Uncertain`, including lost ACK. This is deliberately conservative, not evidence that every attempted open mutated the service. A consumer must reconcile an uncertain result; the shell never redials, restarts an operation or replays consumed bytes. Transport ACK is not durable publication, completed migration or destination-resume authority. A lost terminal result also does not authorize replay of a registered effect. The canonical evidence schema and dependency cohort are unchanged.

Actual path readback distinguishes `direct-loopback`, `direct-ip` and unavailable observations. Relay/discovery/bulk fallback are unsupported and never silently selected. Direct-IP evidence alone does not establish two hosts or prove throughput, WAN/NAT traversal or control-plane fleet responsiveness.

## Cancellation ownership review

This is a source-backed inventory of the selected direct-stream API, not a runtime-wide cancellation audit. The transport maintainers own the [operation shell][direct-operation], [pump][direct-pump], [listener][direct-listener], [outbound owner][direct-outbound] and [registered-effect adapter][direct-registered]. The current executable consumers are the [private-socket fixture][socket-service] and [cancellation service][cancel-service]; the [unreachable denial fixture][unreachable-service] deliberately panics if authority/open is dispatched. There is no in-tree production `ProtectedSocketService` implementation supplying VM authority. A downstream protected-service implementer owns effects and unfinished work inside its `open` future, current-authority checks and application reconciliation; Kiln owns the external migration semantics.

| Boundary and selected future | Ownership, resumability and finite bound | Independent effect/resource evidence and consequence |
| --- | --- | --- |
| Observation: cancellation watch, local readiness, incoming-header `read` | Losing a branch of the pump's `select!` may drop a pending cancellation-safe `read`. `Transfer.header_bytes` and its nine-byte buffer survive local-readiness wins; a consumed prefix is not restarted. The watch is observation only; sender loss is cancellation. Idle and total deadlines bound the driver. | Peer-written partial prefixes and independently read local payload distinguish retained header progress from a replayed/misaligned header. This resumability is **inside the same live driver**, not a promise that a dropped API invocation can be resumed. |
| Admission: endpoint accept/handshake, source gate, authenticated peer/operation binding, `authorize` | Waiting for an incoming attempt has no protected-service dispatch. Once `AcceptSession` applies, the listener owns its sole reservation, even before a connection handle exists. The handshake/preface are total/idle bounded; preface `read_exact` is terminal on interruption, never retried. Gate/authority/currentness decisions and generation transitions are synchronous, with no await between check and state mutation. | Independent service-open counts and protected peers must remain untouched on wrong binding/generation or pre-open cancellation. A consumed rate token is not refunded. A reserved interrupted handshake requires endpoint close/drain; merely dropping its future is not cleanup. Synchronous consumer callbacks must themselves be bounded/nonblocking: an async timeout cannot preempt one. |
| Protected `open` | [The port][protected-port] returns an arbitrary consumer future, not a cancellation-safe observation. `SocketService::open` rechecks authority, increments opens and awaits a real Unix connection. The cancellation service takes a real socket, writes `OPEN_EFFECT` (`0x73`) and waits **before returning it**. The operation sets `is_open_started` before the idle-bounded await; total cancellation can also interrupt it. | The Unix peer's byte and subsequent EOF are independent of the receipt classifier. No returned socket and zero byte counters cannot establish non-delivery. Interrupted open is terminal, not resumable; the service owner must reconcile any remote/open-side effect or separately owned resource. Transport cleanup does not certify application rollback. |
| Local consumption and partial outbound header/digest/body writes | A local `read` result is counted before the next authority check/await. `submitted` is set before DATA header writing. The buffer and pending sequence belong to one driver; no second local frame is consumed while one is unacknowledged. Writes have idle bounds inside the total deadline. Exact byte/frame limits permit only the documented one-byte overflow probe. | A real local producer/remote receiver can observe consumption/submission even if `sent_bytes` has not advanced. Partial writes end this operation; neither the frame nor an overflow byte is silently retried. Revocation after consumption yields uncertainty, not stale-generation success or restored bytes. |
| Partial inbound digest/body reads | After a complete header, bounded `read_exact` calls fill the one inbound frame buffer. They are **not** selected against local readiness and restarted. Idle/total cancellation destroys the operation rather than resuming an unknown partial body. Length/frame/total bounds and digest validation precede a protected write. | Raw peer fragments and protected-peer reads distinguish network consumption from protected delivery. An incomplete/digest-invalid frame must not appear at the protected peer. No fresh operation may replay consumed wire bytes under an old request. |
| Protected local `write_all` | After digest/current-authority checks, receive progress is marked before the potentially partial socket write. The write is idle/total bounded, not cancellation-safe/resumable across operations. ACK is sent only after it completes. | Read actual bytes at the Unix peer while withholding its reads to exercise backpressure; counters alone cannot prove a full write. A cancelled/failed write can have a visible prefix and remains uncertain. Closing a transport cannot undo bytes already delivered locally. |
| ACK send/receive | Sequence plus digest must match the one pending frame. ACK digest reads and writes are idle/total bounded. Only full matching ACK consumption clears `pending` and advances acknowledgement progress. Lost/delayed ACK terminates without another local-frame read/replay. | The protected peer may already have received the complete payload while the sender lacks an ACK. Independently withholding/releasing the ACK distinguishes that case from non-delivery. ACK proves the selected bounded socket-write boundary, not durable application commit. |
| FIN, local shutdown and stream finish | `local_write.shutdown()` precedes FIN ACK. Both half-closes and pending ACK completion precede `send.finish()`, the one-byte trailing-EOF probe and `send.stopped()`. These completion observations have an idle bound within the total budget. | Protected-peer EOF and raw-peer FIN/ACK/EOF observations are distinct from declaring `Clean`. Cancellation after half-close can leave an effect with no clean terminal result. No completion join may turn an unresponsive peer into an unbounded wait. |
| Cleanup: connection/endpoint close and `drain_and_close` | Cleanup runs **after** the cancellation/total-timeout selection under its separate finite budget. Listener cleanup releases its reservation and applies session cleanup only when observed; timeout drains admission and retains the reservation. Outbound cleanup keeps the endpoint alive for clean peer closure, then closes it. `drain_and_close` is separately bounded. | Peer closure/EOF, endpoint state and denied subsequent admission must support the cleanup/capacity claim independently of receipt booleans. `cleanup_observed=false` means unfinished/unobserved ownership, not permission to reuse the slot. A local reset flag alone is insufficient. These observations cover owned local transport resources, not termination of arbitrary work spawned by a service implementation. |
| Outer API drop, abort or lost registered receipt | Dropping `accept_proxy`/`proxy` bypasses the post-selection cleanup and evidence builder; ordinary Rust resource drop is not an awaited close. The listener reservation already stored in `self` is not released by an unobserved terminal result. [Registered dispatch][direct-registered] consumes the request before awaiting network effects; dropping that future also skips its subsequent control `CloseStream`. | There is no fabricated terminal/cleanup receipt, capacity release or automatic replay. Retain/quarantine the owner and reconcile the old operation; signal cancellation and keep polling to bounded terminal evidence when a managed stop is possible. An abandoned listener denies later admission, rejects a different generation, and its `drain_and_close` reports the unterminated session as a failure instead of cleanup; discard that owner. A missing result never authorizes duplicate dispatch; even successful control-handle closure is not stream-delivery evidence. |

The [interrupted-open regression][cancel-regression] uses real Iroh endpoints and `UnixStream::pair`, with the protected peer's `0x73` read as an explicit pre-cancellation barrier and peer EOF checked independently afterward. Its original failing observation established the zero-byte false-`NotDelivered` defect; the fix is the pre-await marker, not a synthetic grant, a new schema field or an assumption about how `open` behaves. The [barrier scenarios][cancel-transfer] cover partial header and body reads, a completed and a backpressured protected write, a withheld ACK, stream shutdown, the actual outbound cleanup-timeout branch and a clean partial-header completion, interrupted by cancellation, a deadline or an outer drop where reachable. Each records barrier and interruption timing, independently observed protected bytes and EOF or reset, retained progress and any unfinished owner or resource; the independent ledger rejects deliberately broken progress and cleanup records. The 2026-11-17 parent run passed all 19 in-process scenarios plus the registered-request drop test, with [retained observations][cancel-evidence]. It is same-host loopback evidence only.

### Pinned Oxide comparison: no adoption at these sites

The review uses primary `oxidecomputer/cancel-safe-futures` sources pinned to [`ca46c04cce2c7de8eb56be2329abd2c56282a4a3`](https://github.com/oxidecomputer/cancel-safe-futures/tree/ca46c04cce2c7de8eb56be2329abd2c56282a4a3), not moving docs/latest. No dependency or transport abstraction is added.

| Candidate and pinned source | Exact matching-site decision |
| --- | --- |
| [`SinkExt::reserve`][oxide-sink] and synchronous [`Permit::feed`][oxide-permit] separate `poll_ready` from `start_send`; `send` additionally returns an asynchronous flush. | **Do not adopt:** the direct pump writes Iroh/Unix byte streams, not a `futures_sink::Sink<Item>`. Its selected-read header state, owned frame buffer, pre-await consumption/submission markers and one-pending-frame rule already expose the irreversible boundary. A Sink wrapper would not make byte writes or protected `open` reversible and would introduce an unnecessary second convention. |
| [`join_then_try!`][oxide-join] runs all listed branches through errors; it stores futures inline and does not impose deadlines or survive dropping the joined parent. | **Do not adopt:** the pump is one explicitly ordered driver, not a fail-fast join of independent cleanup effects. `refuse_excess` intentionally runs until the operation ends, so joining it to completion would hang without an outer budget. Stream finish and owner cleanup already have finite, separate budgets and ordered ownership. If future independent completion obligations require a join, all branches still need finite bounds and individual outcome accounting; the macro alone supplies neither cleanup evidence nor outer-drop safety. |
| [`coop_cancel`][oxide-coop] provides fan-in explicit cancellation plus an optional `Waiter` that observes **receiver drop**; its implementation uses an unbounded message channel. | **Do not adopt:** the watch already expresses the required signal and sender-loss cancellation without a cancellation-message backlog. The live API future owns the bounded cleanup phase. Receiver-drop notification would not prove a protected write, connection close or reservation release, and changing channels would not repair an arbitrary outer drop. The relevant fix is truthful uncertainty before `open`, not a different notification type. |
| [`RobustMutex`][oxide-mutex] offers synchronous action callbacks or poisoning on cancellation of async callbacks. It detects potentially broken guarded invariants, not external-effect rollback. | **Do not adopt:** the selected state is uniquely owned through `&mut Acceptor`, `&mut Registered`, service and pump references; no selected mutex guard spans these awaits. Listener reservation and consumed-request fencing already remain conservative after interruption. Introducing a mutex merely to poison it would not observe socket cleanup, reconcile an external service effect or permit replay. |

This decision is confined to the inventoried call sites. It is not a claim that cancellation is generally safe, that arbitrary service futures are droppable, or that unrelated runtime loops need no review. Maintenance changes that add spawned work, a shared async critical section, Sink-based queueing or independent joined cleanup must reopen this ownership decision. External two-host/Kiln/Cloud Hypervisor prerequisites remain unchanged.

## IPv6 address hints and host-local scope

IP hints cross host boundaries in two places: node live tickets (`live_ticket_address_refs` exports, `live_ticket_endpoint_addr` imports) and cross-process endpoint locators (`endpoint_locators` exports, `endpoint_addr` imports). Both use the shared admission in [`src/fabric_transport/address/mod.rs`](../src/fabric_transport/address/mod.rs). Direct-stream bind addresses are local configuration, not exchanged hints; `validate_bind` keeps its own explicit-unicast rule.

An exchanged hint admits unicast IPv4 (including loopback) and unicast IPv6 (global, unique-local or loopback) with zero `flowinfo` and zero `scope_id`. It rejects unspecified and multicast addresses, link-local IPv6, a nonzero flow label (the textual form cannot carry it), and a nonzero scope id (an interface index on the sender does not name an interface on the receiver). Producers omit local addresses outside this domain rather than publishing them in a lossy or host-local form; consumers reject such a hint, naming the field, instead of reinterpreting it. For every admitted hint the textual round trip preserves address, port, flow label and scope.

Compatibility: loopback tickets and unscoped IPv4 or IPv6 hints are unchanged. A ticket or locator carrying a scoped, link-local or flow-labelled IPv6 hint, which earlier code accepted or silently truncated, is now rejected; no supported consumer dials link-local or scoped peers. Hints stay subordinate to the authenticated Iroh identity, admitted peer context, protocol and generation, and admitting a hint grants no authority.
