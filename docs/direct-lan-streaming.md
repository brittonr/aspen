# Admitted direct-LAN streaming

Aspen exposes the explicit `molten-iroh-direct-lan-stream-v1` implementation profile through its existing cross-process Iroh transport. `molten` remains the internal crate/CLI/schema name. This document describes the consumer contract, not a claim that a two-host or VM migration run has passed.

## Selection and compatibility

The selected dependency cohort is registry **Iroh 1.0.0**, backed by **NOQ 1.0.0** in this repository's lockfile. The existing explicit-loopback `Listener`/`exchange_frame` conformance API and its canonical artifacts are unchanged. Direct streaming is a separately selected profile: it does not widen the loopback profile's bind policy or turn its receipts into cross-host evidence.

At Kiln revision [`90acb852940fa97aa55b4cc1559db835d1dacc12`](https://github.com/OnixResearch/kiln/tree/90acb852940fa97aa55b4cc1559db835d1dacc12), the workflow adapter selects Iroh **0.95.1**, while `runtime/kiln-aspen-host` selects an older Aspen/Molten revision. Those are not the selected stream cohort. No external repository, dependency pin or lockfile is changed here, and 0.95.1/1.0.0 wire compatibility is **not** asserted.

The explicit compatible composition to evaluate is a Kiln migration-side host bridge built against this Aspen revision and its Iroh 1.0.0 closure. It uses this public protected-socket API, rather than passing Iroh 0.95.1 connection types across the boundary. Kiln's existing 0.95.1 workflow control adapter remains separate and unchanged. Kiln must select and retain its exact host-runtime revision, complete dependency closure, migration adapter and Cloud Hypervisor version before that composition can be qualified. A source-level handoff is not execution evidence or permission to repin Kiln silently.

## Consumer API and authority order

The public Rust facade is `molten::fabric_transport`:

1. Supply the canonical `Profile` and `ProtocolDescriptor`, exact active generation, endpoint capability, explicit numeric unicast bind and direct IP handoff. `validate_direct_stream_bounds` requires the direct profile id, one admitted connection and one bidirectional stream. Do not use wildcard binds, relay/custom locators, ambient discovery or endpoint fallback.
2. The server calls `direct::Acceptor::bind(direct::Config)`; its configured peer context must equal `listener.expected_peer_context_ref` before binding or publishing a handoff. The client supplies `direct::Outbound { input, peer, bounds, request, clock }` and calls `direct::proxy`. `input` retains the normal exact endpoint-import expectations. Both configuration inputs and `RegisteredStreamRequest` receive an explicit monotonic `clock: fn() -> std::time::Instant` from the imperative consumer, normally `std::time::Instant::now`. These compose existing endpoint, listener and session owners; there is no new transport, scheduler or membership protocol.
3. A complete Iroh handshake supplies the actual `Connection::remote_id()` and negotiated ALPN. The binding must match the configured EndpointId, peer context, service, ALPN, remote client/listener role and active generation. Expected peer context is applied only in conjunction with an exact authenticated key match; it is not accepted merely because it was copied from a handoff.
4. The listener derives the rate source from `Incoming::remote_addr()` (IPv4 address or IPv6 /64, not a cheap-to-mint endpoint identity). `ReceiveGate` consumes an injected-time budget before the costly service handler. Only this gate constructs non-Clone `GatedInbound`; both private construction and the actual protected-service handler boundary have compile-fail coverage. The limiter covers service admission, **not** all QUIC/TLS handshake CPU.
5. The peers exchange a fixed 32-byte canonical operation-binding digest before payload. It binds request, operation, protected resource, generation and the complete stream contract. A mismatch denies before opening a local socket. Full-handshake-only APIs and an explicit `RecvStream::is_0rtt()` check refuse replayable early stream operations.
6. Implement `ProtectedSocketService::authorize(GatedInbound, &DirectStreamRequest)`. This trusted consumer port resolves current membership, application principal, trust, capability, expiry and revocation for the exact operation. It returns a canonical evidence ref, not an authority grant inferred from connectivity. No default production authority or fixture fallback is supplied.
7. `check_current(&direct::AdmittedOperation)` runs before local opening and each frame. `open` receives a privately constructed admitted operation and returns a protected `tokio::net::UnixStream`. The consumer must resolve it through its existing protected root and recheck currentness at the protected effect; the transport accepts no ambient socket path.

For registered extension effects, retain the existing `Registered` port and register a payload-free bidirectional `TransportCommand::OpenStream`. Call `Registered::proxy_stream` with `RegisteredStreamRequest`, the exact canonical binding and typed effect. The ordinary `FabricEffectPort::route` rejects `OpenStream` for the direct-stream profile; other profiles retain control-only setup for their bounded-frame path. Both the registered request reference and `OpenStream.operation_id` must match the protected request before applying a transition. Existing extension/service/generation/profile/target admission still precedes the transition, and the request is consumed before network effects. The protected stream never enters `Registered`'s `Vec<u8>` frame queue. Its terminal evidence, not closure of the control handle, owns delivery and uncertainty.

Neither endpoint possession, successful source admission, authenticated peer identity, a historical receipt nor transport ACK grants VM/storage authority. Kiln retains workflow attempt, placement, destination resume, migration cutover and result authority.

## Bounds and lifecycle

`DirectStreamBounds` is explicit and included in a canonical stream-contract ref exchanged by both peers:

- One admitted operation/connection and one bidirectional stream; the mutable listener serializes callers. Extra incoming attempts are refused while the selected operation runs. There is no spawned transfer worker or hidden transfer queue.
- A maximum payload frame size (at most 1 MiB), total payload bytes **per direction**, frame count **per direction**, idle timeout, total operation deadline and separate `cleanup_timeout_ms` (each total/cleanup deadline at most 300,000 ms). Operation execution and its cleanup have separate finite budgets; the timeout does not silently abandon cleanup or claim it succeeded.
- Two fixed application frame buffers. QUIC receive and send windows are each `2 * max_frame_bytes + 512`. The admitted queued/in-flight payload/control budget must therefore be at least `6 * max_frame_bytes + 1024`, and at most 64 MiB. No VM RAM image is collected in memory.
- Pending unauthenticated handshakes are a separate selected-runtime bound: NOQ 1.0.0 defaults to 65,536 pending attempts, 10 MiB buffered per attempt and 100 MiB aggregate incoming buffered data. Iroh 1.0.0 does not expose a builder setter for these endpoint-wide defaults. These bounds are **not** included in `max_buffered_bytes`, and this source gate does not claim pre-TLS DoS protection. An operator needing smaller endpoint-wide unauthenticated bounds needs an admitted upstream/configuration change; do not report the application payload limit as a total endpoint/RSS bound.
- One unacknowledged outbound frame, no application frame backlog, QUIC backpressure and no consumption of another local frame until its acknowledgement. After an exact byte/frame bound, a one-byte overflow/EOF probe is the maximum extra local consumption; a consumed overflow is reported and never replayed.
- Partially read headers remain in the driver across readiness changes. Cancellation-safe `read` is selected against local readiness; dropping a partial `read_exact` is not used to restart a header.

The framed stream has a nine-byte kind/unsigned-64-bit prefix. DATA carries a 32-byte BLAKE3 digest followed by the bounded payload. ACK carries the corresponding sequence and digest and is emitted only after a matching bounded protected-socket write. FIN carries zero length, half-closes the protected local writer, and receives an empty-payload digest ACK. Either direction can continue sending after the other half-closes. Both FINs and definitive ACKs precede stream finish, a fixed one-byte trailing-EOF probe, and bounded observation that the peer received all final stream bytes. The listener owns clean connection closure while the client keeps its endpoint alive to acknowledge the listener's final bytes; failure still resets either side immediately. The wire framing is internal to this selected profile, not an interoperability assertion for other Iroh/application versions.

A watch cancellation signal or loss of its owner terminates the operation; idle/total timeouts, revocation, malformed framing, over-bound input and disconnect also terminate it. Local connection close with a nonzero code resets the failed operation. Local connection/endpoint closure is awaited within `cleanup_timeout_ms`; a timed-out cleanup remains `cleanup_observed=false`, even if the earlier byte acknowledgement was definitive. Consumers must check cleanup separately from delivery/stream terminal class. A cancelled handshake without an authenticated connection handle closes and drains its owning endpoint rather than fabricating cleanup from dropping the handshake or silently rebinding. Unobserved listener cleanup stops further admission and retains its active reservation for reconciliation. Dropped futures cannot produce successful cleanup evidence. `reset_observed` means the local connection-reset close was issued and locally observed, not that a remote application acknowledged a reset.

`begin_drain` or `begin_drain_with_reason` stops new protocol admission; registration, capability and profile revocation use the existing drain-reason enum. An active operation is bounded by its deadline and can be stopped through its cancellation owner/current-authority port. After its terminal observation, `drain_and_close` awaits endpoint cleanup. An already-draining listener is completed without applying a second BeginDrain transition. A pending/new generation cannot inherit an old consumed operation.

## Delivery evidence

Every completed API invocation returns canonical `direct::Evidence.value` and its BLAKE3 `evidence_ref`. It binds exact descriptor, operation, contract, actual authenticated peer (when available), configured peer context/service/ALPN/role/generation, observed direct path class, bytes/frames, local consumption, acknowledgement count, duration, receive denial code, operation-authority evidence and local cleanup. Raw payloads, keys, locators and local socket paths are excluded.

`Delivered` means the selected transport/socket-write acknowledgement boundary completed. A failed operation with no local consumption/submission/protected write is `NotDelivered`. Consumption, submission or a possibly partial protected write without full completion is `Uncertain`, including lost ACK. A consumer must reconcile an uncertain result; the shell never redials, restarts an operation or replays consumed bytes. Transport ACK is not durable publication, completed migration or destination-resume authority. A lost terminal result also does not authorize replay of a registered effect.

Actual path readback distinguishes `direct-loopback`, `direct-ip` and unavailable observations. Relay/discovery/bulk fallback are unsupported and never silently selected. Direct-IP evidence alone does not establish two hosts or prove throughput, WAN/NAT traversal or control-plane fleet responsiveness.

## Qualification and exact external prerequisites

The executable consumer fixture is `tests/directlanstreams.rs`. Its parent launches independently configured listener/client/raw-peer child processes, observes readiness, bounds and reaps children, and uses real private Unix sockets. Fifteen direct-stream cases cover multi-frame request/response, crossed listener context, wrong authenticated peer, stale generation/restart, current authority revocation, wrong ALPN/resource scope, oversized prefix, slow partial header, disconnect, actual consumed-data ACK loss, concurrent connection refusal, cancellation and drain. The parent subsequently ran the repaired suite: all 24 tests passed (15 direct-stream cases and nine workspace controls). The standalone child-role entrypoint is ignored only when enumerated without parent-provisioned configuration; the parent invokes it during real cases.

Parent verification commands, **not run by the implementation workers**:

```sh
cargo test -p molten-core fabric_transport::receive
cargo test -p molten-core --doc
cargo test -p molten --lib fabric_transport
cargo test -p molten --doc
MOLTEN_DIRECT_STREAM_EVIDENCE_DIR="$PWD/target/direct-stream-evidence-review-1" \
  cargo test -p molten --test directlanstreams -- --test-threads=1
```

Choose a fresh explicit evidence directory for each retained run. Each case is create-only and retains native listener/client `.preserves` outputs plus `artifact-index.preserves` binding their canonical hashes. Payload fixtures, raw locators, private keys and local socket paths are not copied. Without the retention variable, ordinary test-workspace cleanup applies. This index is a bounded child-output inventory, not independent two-host/process attestation or a fabricated passing qualification receipt.

`MOLTEN_TEST_DIRECT_LAN_IP=<explicit-local-unicast-IP>` selects a named local NIC for the same-host suite. Without it the suite uses explicit loopback, under the distinct direct-stream profile. Neither variant becomes actual two-host qualification. Existing `cluster fabric-transport-run`/`fabric-transport-verify` remain the unchanged legacy loopback distinct-process rail.

Unexecuted external acceptance is deliberate and remains open: two real hosts with provisioned fixed direct addresses/independent keys/current operation authority; exact source/build/closure/features; cross-host bytes/duration/path and fault evidence; the selected Kiln migration bridge; and actual protected Cloud Hypervisor sockets for the pinned consumer cohort. No SSH target/cohort is configured in this assignment. A local `/dev/kvm` device is not a second host or a migration run. [Kiln #54](https://github.com/OnixResearch/kiln/issues/54), [#53](https://github.com/OnixResearch/kiln/issues/53) and [#55](https://github.com/OnixResearch/kiln/issues/55) retain channel integration, paired state transfer/paused handoff and live-migration qualification respectively. Cloud Hypervisor v54 copying/precopy proxying may be evaluated; host-local memfds must never be serialized across hosts, and a byte-stream receipt cannot authorize destination resume.
