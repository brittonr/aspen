# Complete proof checklist example

## Proof claim

The changed traceability gate derives coverage from canonical verification-run receipts and denies stale receipt refs.

## Out-of-scope claims

The change does not claim command logs are normative and does not grant authority outside traceability.

## Trusted assumptions

The receipt parser trusts canonical Preserves decoding and BLAKE3 content refs validated by Molten.

## Positive evidence

- `cargo test trace_core::tests::verification_run_receipts_derive_receipt_backed_coverage --lib`
- Receipt refs from the verification-run fixture are recorded in traceability coverage.

## Negative evidence

- `cargo test trace_core::tests::receipt_backed_policy_denies_raw_compatibility_tuples --lib`
- `cargo test trace_core::tests::verification_receipt_denies_wrong_exit_for_negative_coverage --lib`

## Canonical refs

- Traceability manifest ref: generated by `molten test traceability scan --require-receipt-backed`.
- Verification-run receipt refs: generated by `molten test traceability verification-run`.

## Traceability updates

Positive and negative receipt files are passed with `--receipt`; raw tuples are compatibility-only.

## Hegel RS properties

- `hegel_traceability_decision_law_and_deny_monotonicity`
- `hegel_receipt_ref_stability_and_binding_drift`

## Regeneration commands

```sh
nix develop -c cargo test trace_core::tests --lib
molten test traceability scan --root . --changed-only --require-receipt-backed --receipt target/proof/positive.preserves --receipt target/proof/negative.preserves
```
