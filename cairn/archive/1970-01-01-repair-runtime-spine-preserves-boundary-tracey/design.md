# Design: Repair runtime-spine Preserves boundary-profile Tracey links

## Success contract

A requirement leaves inherited debt only when current implementation and focused validation support its complete accepted wording.
Completion requires nine exact repairs, deterministic typed evidence, zero dangling markers, and full repository validation.

False completion includes treating archived tasks as current proof, treating a declared measurement as an automatic source scan, or promoting canonical identity into trust.

## Search registry

### Typed profile contract

Review the Nickel row and measurement contracts, family coverage, uniqueness, consumer admission, canonical-byte requirement, BLAKE3 refs, adapter-only fields, and non-claims.

### Pure Rust validation

Review `molten_core::preserves_profile` for deterministic issue classification over explicit rows and artifact measurements.
Require positive tests and negative tests for canonical bytes, labels, refs, consumers, non-claims, and raw core coupling.

### Dependency boundary audit

Review `molten-core` dependencies and Rust imports for direct Preserves coupling.
Treat the explicit measurement flag as supplied evidence, not ambient source truth.

### Fixture and documentation audit

Run the valid Nickel fixture and all four invalid fixtures.
Review the modularity guide for exact supported claims and explicit non-claims.

### Persistent validation audit

Add the positive and negative fixture suite to the repository-owned Nix configuration check.
Bind direct-evidence metadata and inherited-baseline state to the existing fail-closed Tracey check.

## Evidence manifest

A typed Nickel manifest records each requirement, implementation path, verification path, evidence scope, and bounded non-claims.
Generated JSON is a deterministic validation input.

## Freshness gate

The inherited Tracey Nix check exports the manifest, compares generated JSON, checks exact counts and unique identifiers, verifies declared markers, and denies repaired baseline entries.
The configuration check exports the valid profile and requires all invalid fixtures to fail.

## Functional boundary

The patch adds marker comments, evidence metadata, and persistent fixture checks.
Production runtime behavior does not change.

## Non-claims

The repair does not prove transport liveness, actor authority correctness, replay completeness, Valence Evidence IR acceptance, universal adapter separation, complete runtime-spine coverage, release readiness, or whole-system correctness.
