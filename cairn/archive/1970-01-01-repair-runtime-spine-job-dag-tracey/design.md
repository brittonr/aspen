# Design: Repair runtime-spine blob-ref job Tracey links

## Success contract

A requirement leaves the baseline only when a specific production location and focused test support its complete accepted wording.
Completion requires nine exact repairs, deterministic typed evidence, zero dangling markers, and repository validation.

False completion includes archive-only evidence, a production check name without exercised behavior, or one local path promoted to a broader replay or integration claim.

## Search registry

### Submission model and denial

Review the canonical submission builder, parser, and inline-token denial tests.
This route can establish the payload model and no-inline-large-bytes requirements.

### Worker execution and evidence lifecycle

Review preflight, fetch, verify, pin, handler, cleanup, status, receipt, and ledger paths with positive and negative worker tests.
This route can establish local worker, content verification, provenance/policy inputs, retention pins, receipts, and local tests.

### Property coverage

Review the bounded Hegel test for inline-token denial, verification-before-run, pin evidence, and cleanup evidence.
This route can establish the property-test requirement.

### Broad replay and integration claims

Adversarially inspect replay identity, all status states, and job-DAG integration.
Keep each requirement uncovered unless the current code and focused tests support the complete wording.

## Evidence manifest

A typed Nickel manifest records each identifier, source area, implementation path, verification path, and bounded evidence scope.
Generated JSON is a deterministic validation input.

## Freshness gate

The inherited Tracey Nix check exports the new manifest, compares generated JSON, checks the exact count and unique identifiers, verifies each declared marker path, and rejects any repaired identifier that remains in the baseline.

## Functional boundary

The patch adds marker comments and evidence metadata only.
Production behavior and test assertions remain unchanged.

## Non-claims

The repair does not establish blob-ref replay identity, complete status-transition coverage, true job-DAG integration, complete runtime-spine coverage, release readiness, or whole-system correctness.
